## 1. The contract in one sentence

**The canonical DTCG token path is the only name anyone chooses.** The Figma variable name, the Tailwind v4 CSS variable, the utility class and the NativeWind config key are all **derived** from it by fixed rules (§4). A generator can produce them without judgement and must fail on any collision (§10).

```
registry path   color.bg.brand-primary-hover          (chosen, reviewed, versioned)
  ├─ Figma name  color/bg/brand-primary-hover          (§8: dots → slashes)
  ├─ Tailwind v4 --background-color-brand-primary-hover → bg-brand-primary-hover
  └─ NativeWind  backgroundColor['brand-primary-hover'] → bg-brand-primary-hover  (same class)
```

## 3. Tiers (unchanged)

There are two token tiers:
- **Primitives:** raw values.
- **Semantic:** roles. Theme-dependent roles live in `tokens/themes/<mode>/`; theme-independent ones in `tokens/semantic/`.

No component tier is introduced, and the **171 component colours stay as they are** (D-05). Composite typography (`typography.*`) is semantic.

## 4. Derivation rules

| Registry path pattern | Tailwind v4 theme variable | Utilities | NativeWind v4 (`theme.extend`) |
|---|---|---|---|
| `color.<family>.<step>` (palette primitive) | `--color-<family>-<step>` **(emitted only when §5 allows)** | `bg-`, `text-`, `border-`, `fill-`, `ring-<family>-<step>` | `colors['<family>']['<step>']` |
| `color.white` / `black` / `transparent` | `--color-white` … (Tailwind already has them, same value: not emitted) | `bg-white` … | built in |
| `color.bg.<role>` | `--background-color-<role>` | `bg-<role>` | `backgroundColor['<role>']` |
| `color.text.<role>` | `--text-color-<role>` | `text-<role>` | `textColor['<role>']` |
| `color.border.<role>` | `--border-color-<role>` | `border-<role>` | `borderColor['<role>']` |
| `color.fg.<role>` (icons) | `--color-fg-<role>` | `text-fg-<role>`, `fill-fg-<role>` | `colors.fg['<role>']` |
| `color.focus-ring.<role>` | `--ring-color-<role>` | `ring-<role>` | `ringColor['<role>']` (§11) |
| `spacing.<n>` (n × 4px) | none: Tailwind's `--spacing: 0.25rem` multiplier | `p-<n>`, `gap-<n>`; `_` → `.` (`spacing.0_5` → `p-0.5`) | default scale; rem note §11 |
| `radius.<step>` | **DEFERRED, see §6** (proposal R1: `radius.<px>` → `--radius-<px>`) | R1: `rounded-<px>` | R1: `borderRadius['<px>']` |
| `font.size.<name>` | `--text-<name>` (+ `--text-<name>--line-height`) | `text-<name>` | `fontSize['<name>']` |
| `font.line-height.<name>` | `--leading-<name>` | `leading-<name>` | `lineHeight['<name>']` |
| `font.weight.<name>` | `--font-weight-<name>` | `font-<name>` | `fontWeight['<name>']` |
| `font.family.<name>` | `--font-<name>` (**`sans` is a default key with a different value: §5**) | `font-<name>` | `fontFamily['<name>']` |
| `font.letter-spacing.<name>` | `--tracking-<name>` | `tracking-<name>` | `letterSpacing['<name>']` |
| `typography.<group?>.<size>.<weight>` (composite) | not a theme variable: `@utility type-…` (§7) | `type-base-medium` | `type['base-medium']` style object (§7) |

**Verified by compile** (`compile-check.mjs`, scenario S1):
- `bg-*` reads `--background-color-*` before `--color-*`. Text, border and ring colours behave the same way.
- So roles get plain classes: `bg-brand-primary`, `text-error-primary`, `border-primary`, `ring-primary`.
- `bg-bg-brand-primary` generates nothing. ADR-0004's hypothesis is confirmed.

**Values are never forced.** The rules give Tailwind-*shaped names*; values always come from the registry (ADR-0005). Tailwind defaults are never copied into the registry.

## 5. Build profile while ADR-0009 is pending — "option A: roles only"

In Tailwind v4, any key in `@theme` replaces the default for **every** screen. Compile scenario S4 showed this: `bg-gray-100` changed from `oklch(96.7% 0.003 264.542)` to `#f5f5f5`. Until the developers decide ADR-0009, the generator emits:

| Token kind | Emitted as | Why |
|---|---|---|
| Semantic roles (`color.bg/text/border/fg/focus-ring.*`) | `@theme` keys (utility-scoped namespaces) | No Tailwind default uses these keys (C4 = 0 for roles) |
| Palette primitives (`color.<family>.<step>`) | `:root { --make-color-<family>-<step>: … }`. Roles point to these. **No palette utilities** | 10 of them (`gray.50`–`gray.950`) share a default key with a **different** value |
| Keys equal to a Tailwind default (`text-base`, `font-semibold`, radius steps, white/black, `tracking-normal`) | **Not emitted.** The build asserts equality instead | Reuse, don't duplicate; zero overrides |
| `font.family.sans` (Inter stack ≠ Tailwind's `--font-sans`) | `:root --make-font-family-sans`, used by `type-*` | Different value; `font-sans` keeps meaning Tailwind's stack |
| Dark mode | Role variables redefined under the dark selector (`.dark { --text-color-brand-primary: var(--make-color-brand-400) }`) | One class name per role, values per mode |

**Result:** existing screens are unchanged. MAKE values are available through role classes. The full list of the 28 shared keys and alternatives B–D for developer review are in `reports/token-naming-conflicts.md` → C4.

## 6. Radius — DEFERRED; proposal R1 (collision-free, no name shifts)

**Status:** radius variables keep their names, values and bindings. Nothing below is applied. R1 replaces ADR-0006's "use Tailwind's name for the same value" rule, so adopting it needs:
1. Mike's approval of an **ADR-0006 amendment**;
2. a **token-repo change**, renaming the registry radius paths and adding one token;
3. a later Figma rename batch.

Each is a separate approval.

### The problem with today's options

| Option | Example | Collision-free? | Names shift? |
|---|---|---|---|
| ADR-0006 as accepted (Tailwind name for the same value) | Figma `radius-sm` 6px → `radius.md` | Yes in code, but **7 of 11 mapped Figma names move one step** (`radius-md` 8px → `radius/lg`), and kept `radius-lg` 10px reads like the renamed `radius/lg` 8px | **Yes** (the reason it was deferred) |
| R0: keep Figma's t-shirt names as tokens | `radius.sm` = 6px | **No**: `--radius-sm/md/lg/3xl/4xl` exist in Tailwind with other values (4/6/8/24/32px) → global override (C4) and docs-vs-code confusion | No |
| **R1: name = px value (recommended)** | `radius.6` = 6px | **Yes**: Tailwind has no numeric radius keys, and compile S3b proved `rounded-6` does not exist until registered | **Never** (a name can't drift from its value) |

### R1 rule

`radius.<px>`, where the key is the value in px (integer; `_` for a decimal point). `0` → `radius.none` and `9999` → `radius.full` keep Tailwind's built-in static classes and are not emitted.
- Figma: `radius/<px>`
- Tailwind: `--radius-<px>` → `rounded-<px>` (plus side and corner variants such as `rounded-t-10`, compile-checked)
- NativeWind: `borderRadius['<px>']`

| Figma today (kept) | px | Registry today (ADR-0006) | **R1 token** | R1 Figma | R1 class | Usage |
|---|---|---|---|---|---|---|
| `radius-none` | 0 | `radius.none` | `radius.none` | `radius/none` | `rounded-none` (built in) | 62 bindings / 4 components |
| `radius-xxs` | 2 | `radius.xs` | `radius.2` | `radius/2` | `rounded-2` | unused |
| `radius-xs` | 4 | `radius.sm` | `radius.4` | `radius/4` | `rounded-4` | 680 / 12 |
| `radius-sm` | 6 | `radius.md` | `radius.6` | `radius/6` | `rounded-6` | 596 / 13 |
| `radius-md` | 8 | `radius.lg` | `radius.8` | `radius/8` | `rounded-8` | 148 / 9 |
| `radius-lg` | 10 | — (none) | **`radius.10` (new)** | `radius/10` | `rounded-10` | unused |
| `radius-xl` | 12 | `radius.xl` | `radius.12` | `radius/12` | `rounded-12` | 432 / 8 |
| `radius-2xl` | 16 | `radius.2xl` | `radius.16` | `radius/16` | `rounded-16` | 488 / 12 |
| `radius-3xl` | 20 | `radius.2-5xl` | `radius.20` | `radius/20` | `rounded-20` | 1,740 / 19 |

### Checks (C13)

- 12 unique names.
- 0 Tailwind default keys.
- 0 shifts.
- Tailwind's own `rounded-sm/md/lg…` keep their default values: no override, backward compatible.
- Also resolves C11 (`radius-lg` 10px gets its own token), C9 (`rounded-2-5xl` disappears) and ADR-0006's open 10px/20px flag.

### Trade-offs to accept

- **`rounded-6` ≠ `p-6`:** radius numbers are px, while spacing numbers are 4px units (`p-6` = 24px). Mitigations:
  - document it in the code-gen header;
  - a lint rule may ban `rounded-<n>` for values not in the registry. Compile S3 shows they don't exist anyway, so a typo produces no style rather than a wrong one.
- **Designers see numbers instead of t-shirt sizes.** If role names are wanted later (`radius.control`, `radius.card`), they become a **semantic radius tier** that aliases R1 primitives. That is structural and needs its own proposal.

### Bindings

Components bind radius variables by ID, so an R1 rename in Figma would change **no** component. Code that already uses `rounded-md` etc. keeps Tailwind's meaning.

## 7. Composite typography — `type-*` (revised)

**Rule T:** class = `type-` + the token path after `typography.`, with the default body group `text` dropped, joined with `-`.

| Registry token | Class | Figma text style today | Same as (single utilities) |
|---|---|---|---|
| `typography.text.base.normal` / `.medium` / `.semibold` | `type-base-normal` / `type-base-medium` / `type-base-semibold` | `Text md/Regular` / `Medium` / `Semibold` | `text-base font-normal` … |
| `typography.text.sm.normal` / `.medium` | `type-sm-normal` / `type-sm-medium` | `Text sm/Regular` / `Medium` | `text-sm font-medium` … |
| `typography.text.xs.normal` / `.medium` / `.semibold` | `type-xs-normal` / `type-xs-medium` / `type-xs-semibold` | `Text xs/Regular` / `Medium` / `Semibold` | `text-xs font-medium` … |
| *future* `typography.display.sm.semibold` | `type-display-sm-semibold` | `Display sm/Semibold` | — |

- **Values and relationships are preserved.** Each `@utility type-*` is built only from references: `font-size: var(--text-<size>)`, `line-height: var(--text-<size>--line-height)`, `font-weight: var(--font-weight-<w>)`, `font-family: var(--make-font-family-sans)`, and `letter-spacing` from `font.letter-spacing.normal`. No new values; the registry composite keeps aliasing its primitives.
- **Verified** (compile S2):
  - all 8 compile;
  - `md:` and `hover:` variants work;
  - Tailwind 4.3.5 has **no** core `type-*` utility (`type-base` → nothing);
  - `text-base` is unaffected;
  - `text-text-base-medium` is never generated.
- **Why not other prefixes:**
  - `text-*` clashes with colour and size;
  - `font-*` clashes with family and weight;
  - `typo-*` and `typography-*` are longer with no benefit;
  - `body-*` breaks for display styles.
- **NativeWind:** custom `@utility` isn't available in NativeWind 4. The generator emits a `type` style map (`type['base-medium'] = { fontFamily: 'Inter', fontSize: 16, lineHeight: 24, fontWeight: '500' }`) for components, or a plugin, depending on the devs' choice.
- **Figma:** text styles are **not renamed** by this convention yet. The mapping `Text md/Medium` ↔ `type-base-medium` is recorded (registry `com.make.source.figma`). Renaming text styles is structural, with separate approval.
- **Optional later clean-up:** move the registry paths to `typography.base.medium`. Not needed, because rule T already gives clean classes. That would be a token-repo change (separate approval).

## 8. Figma naming rule

- **Name = registry path with `.` replaced by `/`**. Examples:
  - `Colors/Text/text-brand-primary` → `color/text/brand-primary`
  - `Spacing/3 (12px)` → `spacing/3`
  - `Font size/text-md` → `font/size/base`
- **Unchanged:** collection names and order, mode names (`Light mode` / `Dark mode` are matched by name in the sync), values, aliases, scopes, `hiddenFromPublishing`, variable IDs.
- **Renames are ID-based and name-only.** Bindings, aliases and text/effect/paint styles point to variable IDs.
- **Code syntax (D-10, deferred):** once approved, `codeSyntax.WEB` gets the Tailwind variable so Dev Mode shows the code name. Separate approval.
- **Only variables with an approved registry token are renamed** (117 candidates today). Figma-only variables keep their names until a proposal adds their token. Never renamed by this migration:
  - radius (deferred);
  - the 171 component colours;
  - `4. Widths` / `5. Containers`.

## 9. Normalising Figma names into registry paths (for new tokens)

ADR-0004 rules, plus the additions found in the audit:

1. **Family slugs:**
   - `Gray (light mode)` → `gray`
   - `Gray (dark mode)` → `gray-dark`
   - **`Gray (dark mode alpha)` → `gray-dark-alpha`**
   - `Green lime` → `green-lime`
   - **`Rosé` → `rose`** (strip accents)
2. **Semantic roles:** drop the shade note (`(900)`); `_` and spaces → `-`; split run-together words (`on-brandprimary` → `on-brand`).
3. **The group prefix is the role namespace:**
   - `Colors/Background/bg-*` → `color.bg.*`
   - `Colors/Text/text-*` → `color.text.*`
   - `Colors/Border/border-*` → `color.border.*`
   - `Colors/Foreground/fg-*` → `color.fg.*`
   - `Colors/Effects/Focus rings/focus-ring-*` → `color.focus-ring.*`
4. **Sizes:** font size uses Tailwind names where the value matches (`text-md` → `base`). Radius: §6 (deferred).

## 11. Platform notes

- **Default theme scope:** §5 is the interim. Options B–D are for the developers (conflicts report, C4).
- **NativeWind (version UNVERIFIED):**
  - NativeWind 4 resolves `rem` as **14px on native by default**. Pin rem to 16 (or emit px) in the mobile config; to be checked in pilot step 5.
  - React Native has no CSS box-shadow rings, so `ring-*` focus styles need a native equivalent.
  - Placeholder colour on native is `placeholderTextColor`.
- **Dark mode:** one name per role with per-mode values; no `-dark` names for roles.

## 12. Change classes

| Class | Meaning | Allowed together with |
|---|---|---|
| **Cosmetic** | Name changes; value, alias, type, ID unchanged | Only other cosmetic renames in the same batch |
| **Value** | A value or alias target changes (visible) | Never in a rename batch; goes through the sync with per-row approval |
| **Structural** | Token added, merged, split or retyped, or components rebound. Examples: R1's new `radius.10`; replacing `3. Spacing` t-shirt variables; merging C8 duplicates; text styles ↔ `type-*` | Its own proposal and approval |

All 117 rename candidates are **cosmetic**.

## 13. Rollback

Every rename batch stores `{id, oldName, newName}` before writing. Rollback restores names by ID in one call (`scripts/naming/pilot-rename.js` with `ROLLBACK = true`). Renames don't touch bindings, values or aliases, so nothing else needs restoring. Details: `reports/token-rename-migration-map.md` → *Rollback requirements*.
